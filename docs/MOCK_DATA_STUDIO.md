# NUFIELD Mock Data Studio and Scenario Library

> **Important scientific boundary:** all records generated by this package are synthetic interface fixtures. They are not survey observations, measurements, cosmological predictions, calibrated posteriors, or evidence about neutrino mass. The generator does not call CLASS, CAMB, an N-body solver, or the NUFIELD inference pipeline.

## Purpose

The mock-data system supports product walkthroughs, screenshots, frontend interaction tests, table pagination, chart-density testing, loading/empty/error states, validation warning demonstrations, and local import/export rehearsals. The same project contains scientific research code. The mock-data package is deliberately isolated from simulation, reconstruction, and inference modules so a demo cannot silently appear to be a scientific run.

## Quick start

From the repository root:

```bash
python scripts/generate_mock_data.py --profile baseline --seed 90721 --output examples/mock_data/baseline
```

This writes `bundle.json`, named JSON artifacts, optional CSV versions, a checksum index, a short README, and `nufield-demo-artifacts.zip`.

Generate every scenario in one operation:

```bash
python scripts/generate_mock_data.py --profile all --seed 90721 --output examples/mock_data/scenarios
```

The `all` mode creates an independent subfolder for every profile and a ZIP next to the scenario-library folder. It intentionally caps per-profile sizes to make the whole scenario library practical to share. Each scenario receives a different deterministic seed derived from the base seed and stable scenario order.

List profiles:

```bash
python scripts/generate_mock_data.py --list-profiles
```

Request larger data for table and rendering performance checks:

```bash
python scripts/generate_mock_data.py \
  --profile high_resolution \
  --seed 810023 \
  --sample-count 8000 \
  --observation-count 12000 \
  --chain-count 4 \
  --samples-per-chain 1000 \
  --spectrum-points 800 \
  --history-count 250 \
  --field-slices 500 \
  --output examples/mock_data/high_resolution
```

The command has hard caps. It refuses to create negative dimensions and clamps out-of-range counts to the documented safe ranges. Large runs can use significant memory because the consolidated `bundle.json` stores the artifact data together in one file; use smaller values for routine demos.

## Frontend usage

Run the frontend:

```bash
python scripts/serve_frontend.py
```

Navigate to `http://127.0.0.1:8000/frontend/` and open **Mock Data Studio**. The browser-only generator offers scenario selection, seed control, count controls, a generated parameter histogram, a power-curve preview, a filterable parameter table, experiment history, a data-quality panel, fixture validation checks, and JSON/CSV export.

Use **Load demo metadata into diagnostics** to set the generated `dataset.json`, manifest, and benchmark report in the dashboard's existing in-memory importer state. This action only updates local view state. It does not send data to the Python backend and it does not run a model. The parameter-space view consumes a bounded `parameter_points` preview in the benchmark report; the complete table is exported separately.

The browser generator is intentionally bounded to 2,000 parameter rows, 5,000 catalog rows, 8 pseudo-chains, 1,500 steps per chain, 800 spectrum points, and 300 fake history rows. The Python CLI supports higher caps for offline rendering and load testing.

## Scenario catalog

| Profile | Main purpose | Expected fixture behavior |
|---|---|---|
| `baseline` | Happy-path onboarding | Balanced synthetic tables, disjoint split IDs, moderate noise |
| `low_neutrino` | Parameter labels | Lower toy `sum_mnu_ev` center for comparisons |
| `high_neutrino` | Parameter labels | Higher toy `sum_mnu_ev` center for comparisons |
| `noisy_survey` | Data-quality warnings | Larger noise and more masked rows |
| `calibration_bias` | Calibration panels | Artificial offset and calibration warning |
| `domain_shift` | Train/test comparison | Shifted test split and a domain-shift warning |
| `coverage_failure` | Coverage chart | Artificially depressed coverage values |
| `split_leakage` | Split integrity | One realization ID deliberately overlaps split assignments; report should fail the fixture check |
| `sparse_data` | Low-count UI | Smaller implied grid and wider spread |
| `high_resolution` | Large tables and scrolling | Higher implied grid label; combine with larger count options to generate volume |
| `malformed_artifacts` | Importer states | Descriptions for malformed JSON, a valid unclassified object, an array root, and a nesting-depth case |

These profiles describe intended UI behavior rather than different physical cosmologies. Scenario names use familiar cosmology symbols for UI realism; the generated values are not fitted to observational constraints.

## Artifact inventory

- `dataset.json`: dataset metadata compatible with the current frontend importer, including `physics_level: "toy"`, feature names, parameter names, counts, seed, and caveats.
- `dataset.manifest.json`: generator identity, options, scenario, filenames, and scientific provenance boundaries.
- `benchmark_report.json`: synthetic median-absolute-error values, coverage placeholders, split IDs, a bounded set of parameter points for the scatter chart, and a clear warning.
- `parameter_samples.json` / `.csv`: complete generated parameter table with unique row IDs, realization IDs, split labels, synthetic scores, and quality flags.
- `posterior_chains.json` and `posterior_chain-N.csv`: random-walk-looking traces for chart layout only; they are not samples from a fitted posterior or a production MCMC algorithm.
- `power_spectrum.json` / `.csv`: arbitrary positive curve values over a logarithmic display range; these are not a physical transfer function or CLASS/CAMB output.
- `expansion_history.json` / `.csv`: redshift and scale-factor relationship plus a deliberately arbitrary distance index. Only `a = 1/(1+z)` is treated as a definition.
- `survey_catalog.json` / `.csv`: generated RA/Dec-like coordinates, redshift-like values, toy density proxies, uncertainty-like values, completeness and mask flags.
- `cmb_summary.json` / `.csv`: hand-shaped synthetic multipole-like curve, not a CMB observation or Boltzmann solution.
- `lensing_catalog.json` / `.csv`: point-mass equation positions in arbitrary angular units with small display noise; not inferred real lens systems.
- `validation_report.json`: expected PASS/WARN/FAIL fixture states.
- `experiment_history.json`: fictional run records for a timeline, statuses, warning pills, and score cards.
- `ablation_report.json`: fabricated component-comparison rows.
- `data_quality_report.json`: descriptions and statistics about the generated catalog only.
- `field_summary.json`: one-dimensional illustrative density and velocity proxy arrays, not a volumetric simulation.
- `import_error_examples.json`: available for the `malformed_artifacts` profile. The malformed raw-text example is intentionally not valid JSON.
- `checksums.json`: SHA-256 checksums for the written files present before that checksum file itself is written. Hashes check byte integrity, not truth or provenance.
- `bundle.json`: a consolidated container holding the artifacts and summary counts.

## Reproducibility contract

For a fixed seed and option set, numeric data rows and artifact shapes are reproducible. Output timestamps are wall-clock metadata and may differ between invocations. Python uses private `random.Random` streams derived per artifact; it does not use or mutate NumPy's global random state. The browser generator uses a seeded PRNG and likewise labels timestamp metadata separately.

The Python generator has separate random streams per artifact family. This means small changes to one output builder are less likely to shift every other artifact's random sequence. It is still a demo generator, not a permanently versioned scientific data contract: generator-version changes may intentionally alter row values.

## Validation and interpretation

The built-in validation report checks generated fixture properties: required shape, finite values, synthetic provenance, split-ID uniqueness, and demo coverage behavior. A report marked `PASS` does not indicate physical accuracy, a correct likelihood, parameter recovery, model calibration, correct uncertainty intervals, or reproducibility of a scientific experiment. A deliberate leakage profile should emit a `FAIL` and is included to verify warning handling.

The `median_absolute_error` and `coverage_diagnostic` values are synthetic UI fixtures. They must not be placed in resumes, papers, grant applications, investor materials as scientific results, or research conclusions. Do not remove the warning fields from the outputs to make screenshots seem more convincing.

## Extending a profile safely

1. Add a `DemoScenario` definition in `src/nufield/demo_data/profiles.py`.
2. Give it an explicit profile ID, a description, center values inside the display ranges, and an optional named stress behavior.
3. Add assertions to `tests/test_demo_data.py` describing the expected state.
4. If you add a new artifact, update `build_demo_bundle`, the stable artifact registry, the CLI export inventory, and this document.
5. Keep the schema labels explicit: append `_toy` to generated physical-looking quantities unless a quantity is a standard definitional relation.
6. Ensure every JSON artifact has synthetic provenance and a science warning. Never label a generated trace as a posterior from the production inference model.
7. Keep production simulator and inference imports out of `nufield.demo_data`.

## Tests

```bash
# Frontend generator, importer, chart helpers, and the original visual lab tests
cd frontend && npm test

# Python library and mock-data integration suite
cd .. && PYTHONPATH=src pytest -q
```

The JavaScript tests cover deterministic seeded rows, range limits, schema compatibility, output serialization, split overlap, coverage failure, domain shift, catalog shapes, and artifact export lists. The Python tests additionally exercise file output, CSV row counts, ZIP integrity, checksum matching, option clamping, and all scenario profiles.
